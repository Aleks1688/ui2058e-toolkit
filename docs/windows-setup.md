# Настройка Windows: драйвер, COM-порт, типовые ошибки

Проверено на Windows 11 24H2 с FTDI FT231X.

## 1. Драйвер FTDI

Кабель прибора определяется как **FTDI FT231X** (`VID_0403 / PID_6015`).
Нужен драйвер **FTDI CDM (VCP)**, свежий — 2.12.36.x (WHQL, 2024).
Старые 2.12.00.x (2014) Windows 11 блокирует при включённой изоляции
ядра: устройство получает **код 39 / STATUS_DRIVER_BLOCKED**.

Установка из пакета в `drivers/ftdi_cdm.zip`:

```powershell
# от администратора
cd <проект>\drivers
Expand-Archive ftdi_cdm.zip -DestinationPath cdm -Force
pnputil /add-driver cdm\*\usbbus.inf  /install
pnputil /add-driver cdm\*\usbport.inf /install
pnputil /scan-devices
```

Или вручную: правой кнопкой по `ftdibus.inf` → «Установить», затем
то же для `ftdiport.inf`.

Альтернатива — установщик с сайта FTDI (CDM Windows Driver).
После установки в диспетчере устройств появляются:

- «Контроллеры USB» → **USB Serial Converter**;
- «Порты (COM и LPT)» → **USB Serial Port (COMx)**.

## 2. COM-порт

Порт определяется автоматически в `ui2058_measure.py` через реестр:

```
HKLM\HARDWARE\DEVICEMAP\SERIALCOMM
    \Device\VCP0 = COM7
```

Приоритет отдаётся именам, содержащим `VCP` или `FTSER2K`; если такого
нет — используется `COM7`. Явно: `--port COM9`.

Сменить номер порта: диспетчер устройств → USB Serial Port → Свойства →
Параметры порта → Дополнительно → Номер COM-порта.

Подпись устройства в диспетчере может врать (например, «COM28»), если
номер когда-то меняли: реальный порт — тот, что в `SERIALCOMM`.
Самый надёжный способ проверить — открыть его нашим ридером.

## 3. «Пропал COM-порт», устройство отключено

Симптом: в системе нет COM-порта, хотя кабель вставлен.

Причина: Windows «выключила» USB-устройство (**код 22**, Disabled,
`ConfigFlags=1`) — обычно после сбоя питания USB или плохого контакта.

Лечение:

1. Диспетчер устройств → «Контроллеры USB» → **USB Serial Converter**
   (стрелка вниз на значке) → «Включить устройство».
2. Или от администратора:

```powershell
pnputil /enable-device "USB\VID_0403&PID_6015\<серийный номер>"
pnputil /scan-devices
```

Серийный номер виден в свойствах устройства (`Get-PnpDevice`).

После включения **перезапустите программу**, которая держала порт:
старый handle уже недействителен.

Профилактика: вставлять адаптер напрямую в порт ноутбука, не через
hub/удлинитель.

## 4. «通讯联络失败!» в фирменной программе

Это значит: команда ушла, ответа нет. Порт при этом может быть открыт
нормально (пока `UI2058.exe` работает, снаружи он занят — это норма).

Проверять по порядку:

1. COM-порт на месте (раздел 3).
2. Кабель вставлен до щелчка, прибор включён.
3. Прибор находится на измерительном экране, а не в «выходе из режимов».
4. Перезапустить прибор и программу.
5. В программе: меню «Тест» → «一键测试稳态参数» (быстрый замер).

Если ничего не помогло — проверить обмен нашим ридером
(`python ui2058_reader.py --seconds 10`): если данные идут, проблема
в программе, а не в кабеле.

## 5. Масштаб экрана и фирменная программа

`UI2058.exe` — старое 32-битное приложение (Delphi), рассчитано примерно
на 1900 точек по ширине. При масштабе 175 % правая часть таблицы
обрезается; при 150 % помещается целиком. Нашему окну это не мешает —
оно подстраивается под DPI.

## 6. Права на папку программы

`C:\Program Files (x86)\Volnic\UI2058E ...` по умолчанию только для
чтения. Если программа не сохраняет настройки/результаты — выдать
текущему пользователю права на запись (или запускать от администратора).
Файл настроек — `UI2058.ini` (там же прописан COM-порт).
